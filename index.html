Accept crypto payments with the Plaxswap API

A short quickstart for developers who want to take Bitcoin, USDT and other coins on a website. It covers the four steps you need: create a payment, send the customer to the hosted checkout, verify the signed webhook, and try every outcome in test mode.

The API is JSON over HTTPS. Coin amounts are decimal strings such as "99.5", never floats, and times are ISO 8601 in UTC. A coin on one network has an id such as usdt-tron, usdc-base or btc. The full reference, with every field and status, is on the Plaxswap payment API docs, and the machine-readable spec is at https://plaxswap.com/api/v1/openapi.json.

1. Get test keys

Open a merchant account on the Plaxswap merchants page, finish the business profile and turn on your authenticator. In the merchant dashboard, open Developers. Make a test key (it starts with pxs_test_), save your webhook URL and make a signing secret (whsec_). Each key and secret is shown once. Keep them on your server only, never in a web page or an app.

2. Create a payment

Your server asks for a payment with the price and your order number. Add an Idempotency-Key header so a retried request returns the same payment instead of a second one.

curl -s -X POST https://plaxswap.com/api/v1/payments \
  -H "Authorization: Bearer pxs_test_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: shop.example-order-1042" \
  -d '{
    "amount": "100",
    "currency": "USD",
    "receive": "usdt-tron",
    "orderId": "1042",
    "returnUrl": "https://shop.example/orders/1042/thanks",
    "cancelUrl": "https://shop.example/cart"
  }'

The answer is the payment object, with an id like pay_..., a status of pending and a checkoutUrl. Store the payment id next to your order.

3. Send the customer to hosted checkout

Redirect the customer to checkoutUrl. On the checkout page they pick a coin, see exactly how much to send and where, and send it. When they are done they come back to your returnUrl. Do not trust that return on its own: read the payment from your server with GET /api/v1/payments/:id, or wait for the webhook, before you show the order as paid.

4. Verify the signed webhook

When a payment changes, Plaxswap sends a POST with the whole payment in data. The x-px-signature header looks like t=<unix seconds>,v1=<hex>, where the hex is an HMAC-SHA256 of t + "." + raw body, keyed with your full webhook secret. Check it against the raw body, refuse timestamps older than five minutes, and answer with any 2xx within eight seconds.

import crypto from "node:crypto";

function verify(rawBody, header, secret) {
  let t = null; const v1 = [];
  for (const part of String(header || "").split(",")) {
    const [k, v] = part.trim().split("=", 2);
    if (k === "t") t = v;
    if (k === "v1") v1.push(v);
  }
  if (!t || !v1.length || Math.abs(Date.now() / 1000 - Number(t)) > 300) return false;
  const expected = crypto.createHmac("sha256", secret)
    .update(t + ".").update(rawBody).digest("hex");
  return v1.some(sig => sig.length === expected.length &&
    crypto.timingSafeEqual(Buffer.from(sig), Buffer.from(expected)));
}

The same event can arrive twice, so remember event ids you have handled. Before you ship, fetch the payment again from the API and check that its status is paid, that the amount, currency and order match, and that livemode matches the key you use.

5. Test every outcome

Payments made with a test key never move real coins. The checkout shows a test banner and buttons that act out each result. You can also do it from your server:

curl -s -X POST https://plaxswap.com/api/v1/payments/pay_ID/simulate \
  -H "Authorization: Bearer pxs_test_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "outcome": "paid" }'

Outcomes are paid, partially_paid, overpaid, late, expired and failed. Each one sends the same webhook a live payment would, with "livemode": false. One test payment takes one outcome, so make a new payment for the next case.

Going live

  • Run a test payment through paid, partly paid and expired, and check your handler does the right thing each time.
  • Check the signature on every webhook and read the payment back before shipping.
  • Swap the test key for a live key (pxs_live_) on your server.

Confirmed payments go to your Plaxswap merchant balance, and you withdraw to your own wallet from there. The platform fee is 1.5% of a payment; the withdrawal fee and network fees are listed on the Plaxswap fees page. Plaxswap is not available in every country.

Example code

Working examples in several languages are in the crypto-payment-gateway-integration repository on GitHub. Plugins for WooCommerce, WHMCS and XenForo are also available if you would rather not write the integration yourself.
